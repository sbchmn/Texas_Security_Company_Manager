Setup

  1. Start the signing profile and configure a trusted HTTPS hostname and certificate. In DocuSeal Settings > Account > App URL, set that same HTTPS origin.
  2. Add its exact HTTPS origin to the operator's DOCUSEAL_ALLOWED_ORIGINS setting. Web and worker containers must resolve the hostname and trust its certificate.
  3. Create a DocuSeal API key and enter it here. Use separate accounts/keys for different tenants; multiple tenants require the licensed deployment agreed for this product.
  4. In DocuSeal, create a template with one signer and a required signature field. Keep I-9 and DPS-issued forms outside this workflow.
  5. Create an onboarding step of kind “A document signed in DocuSeal”, choose a personnel record type and template, and issue the checklist. From the employee's onboarding tab, press “Send signing request”.

The worker checks outstanding submissions every minute, with backoff on failures. “Check signing status” also checks immediately. A timeout during creation is reconciled against the original request, never automatically sent twice. PDFs must be served from this DocuSeal origin; remote object-storage download origins are not enabled in this MVP.

Back up the application database, media, signing database and DocuSeal storage. The encrypted API key also depends on the application's SECRET_KEY; changing that key requires re-entering signing credentials.
