What proves a callback came from the provider. Twilio signs its posts, and when TWILIO_AUTH_TOKEN is configured an unsigned or wrongly signed post is refused outright. Amazon SNS and Mailjet document nothing equivalent on this path, so a post from them is accepted on the strength of the address and TLS, and the retained event is marked unverified. That difference is recorded per event rather than averaged into a general claim about the endpoint.

An SNS subscription also has to be confirmed before AWS will publish anything to it. The confirmation request goes to a URL inside the payload, so this build never follows it on its own — the address arrives in a body that an unauthenticated caller wrote, and fetching whatever such a body names is a way to make this server open its own cloud credentials. Who hears what ({{ rules|length }} rule{% if rules|length != 1 %}s{% endif %})

DD asks for delivery channels to be configurable per audience. A notice reaches several kinds of person at once — the officer it is about, the dispatcher who can act on it, the payroll approver whose number it changes — and without a rule every one of them gets the same in-app copy plus the same email.

A rule chooses, it does not permit. Text still requires the number's own consent below, and a STOP still ends it for everything. That is deliberate: consent belongs to the person and their phone, channel preference belongs to this company, and neither one gets to overrule the other. In-app always arrives whatever you pick here, because it is the durable copy of "we told you" — a text a carrier dropped leaves no evidence at all.
